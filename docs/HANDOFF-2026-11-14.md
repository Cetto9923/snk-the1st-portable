## 4. 关键已证事实（省掉重复排查）

### 4.1 音频

- **第一因**：`nn::codec::DecodeOpus*` 过去是桩函数，**直接把输出 memset 成 0 然后返回成功**。管道、时序、voice 握手全对，所以表现为「跑得很好但全静音」。这一条曾导致整轮误判，别再怀疑管道。
- **容器** `romfs/{bgm1,bgm2,bgm3,se}/nxopus/*.nxopus`，magic `foxn`。头部字段顺序 `ver/ch/rate/totalSamples/seekOff(64)/seekCount/dataOff/dataSize`，实测恒等式 `64 + seekCount*36 == dataOff`、`dataOff + dataSize == fileSize` 成立。
- **帧格式**：游戏交给解码器的是**整块流**（实测 11899 字节），不是单包；帧**自定界**，靠 `pOutConsumed` 回报本包长度（实测按 2 → 68 → 46 推进）。`opus_decode()` 把 self_delimited 标志硬编码为 0，且在解析前就报 corrupted，所以 libopus 里补了薄封装 `opus_decode_self_delimited()`（只选标志，不复制解码逻辑）。
- **`VoiceType` 是标题自己的内联对象**：`AcquireVoiceSlot` 收到它的地址，之后每次调用都传回同一地址。旧实现把自己的指针写进去 → 永远匹配不上 → 所有 wave buffer 被丢弃。必须按标题地址索引。
- **返回码语义**：`Acquire*` 返回 bool（1 = 成功）并交出 64 字节不透明对象；`Add*` 返回 `nn::Result`，**0 才是成功**（返回 1 会被标题当错误打印，然后整张音频图放弃）。
- **`outPcmCapacity` 单位**：8192 → 6272，差值正好 480×2×2，倾向**字节**；但按字节读会触发 7.7 万次重试风暴，按帧读只是第 4 包失败。两种都试过，均未能让标题继续流式。**不要再来回改这一处，问题不在单位。**

### 4.2 图形

- `.xgs` 容器：`XGS1` + 8×u32 头 + 绑定表 + SPIR-V，设备上 613 个。
- 37 个 compute **全部**声明 `LocalSize(1,1,1)`，且确实使用 `WorkgroupId` / `LocalInvocationId`。
- **推导规则：blockDim 只能由「目标尺寸 ÷ 实测派发组数」整除得出，禁止猜测。** 两次猜测（(8,8,1)、(512/1024) 一批）分别造成竖向黑条与纯白屏，已全部回滚。

## 5. 构建环境

需要 JDK 17、Android SDK platform 34 + build-tools 34.0.0、NDK 26.3.11579264、CMake 3.22.1、ninja。
`init-windows.sh` 只做变量注入与预检，不做下载。`source init-windows.sh` 后应有 16 项全 OK。

```bash
source init-windows.sh
bash scripts/android/build_game_window_apk.sh
# 产物 .local/android-apk/snk-the1st-game-window-debug.apk
```

两个已修好的坑：

1. 链接命令行超 Windows 32767 上限（`WinError 206`）→ `build-native-direct.py` 超 24000 字符时写 `link.rsp` 用 `@file` 传参。
2. `-shared` 默认允许未定义符号，`.so` 能链接成功但 `dlopen` 直接崩（曾因缺 `silk_CB_lags_stage2` 崩）。**接新库后必须校验**：
   ```bash
   llvm-nm -u libffrs_game_window.so | awk '{print $2}' | grep -E '^(silk_|celt_|opus_|ec_)'   # 必须为空
   ```

仓库要放**短路径**（如 `C:\snk\snk-the1st-portable`），中文长路径会触发链接长度问题。
